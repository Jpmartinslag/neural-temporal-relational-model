# Data

Raw sources, intermediate tables, and processed panels for the Neural Temporal–Relational
Model. For sourcing, periods, and what is and isn't versioned, read
[`../docs/DATA_AND_PROVENANCE.md`](../docs/DATA_AND_PROVENANCE.md) first — this file gives the
folder layout and a few pointers that document does not repeat.

## Structure

```text
data/
├── raw/        # raw sources; mostly gitignored when large, regenerated by an ingest script
├── interim/    # intermediate tables built from raw sources
└── processed/  # panels, graphs, and targets ready for training or evaluation
```

## Current canonical panel

The France ZE2020 model-ready panel is `data/processed/france_ze2020/fr_ze2020_model_ready_panel.csv`,
built by `src/data/france_ze2020/build_fr_ze2020_model_ready_panel.py`. This is the file
[`scripts/run_minimal_example.sh`](../scripts/run_minimal_example.sh) reads. The synthetic
known-truth benchmark that the neural model's own results in
[`../docs/RESULTS_AND_LIMITATIONS.md`](../docs/RESULTS_AND_LIMITATIONS.md) actually come from is
generated in memory, not read from a file here — see
`src/data/synthetic/generate_france_multisignal_v92.py`.

## Availability and maturity

A feature must be published before the decision date it is used for, not merely dated before
it. For France ZE2020, the current, machine-checked rule is the relation-availability mask:

- `data/processed/france_ze2020/fr_ze2020_relation_availability_mask.csv` (+ `_summary.json`)
- `reports/canonical/HERALD_57_FR_ZE2020_AVAILABILITY_MASKS.md` — the specification
- `src/data/france_ze2020/build_fr_ze2020_relation_availability_mask.py` — the builder
- `tests/test_fr_ze2020_relation_availability_mask.py` — the guard

An earlier version of this file pointed to `reports/HERALD_DATA_AVAILABILITY_CALENDAR.md` and a
matching CSV. Neither exists in this branch (they were never committed — see
[`../docs/EXPERIMENT_PROVENANCE.md`](../docs/EXPERIMENT_PROVENANCE.md) §9); the pointer above
replaces them rather than leaving a reference to a file that isn't there.

## Historical panels, kept for context

Several `data/processed/` files predate the current France ZE2020 focus and are not the current
training input. Kept because they are still documented and reusable for audit, not because they
should be read as canonical:

- `dynamic_stgnn_feature_panel_through_2025_v1.csv`, `target_side_establishments_annual_core_through_2025_v1.csv`,
  `side_creations_a10_ze2020_through_2025_v1.csv`, `graph_adjacency_core_v0.csv`,
  `graph_adjacency_mobility_v0.csv`, `graph_edge_index_core_v0.csv`, `graph_node_index_core_v0.csv`,
  `graph_nodes_ze2020_core_v0.csv` — the pre-Q7 candidate panel and its graph inputs.
- `strict_exante_20260506/`, `leak_stress_20260507/` — leakage-audit stress tests for that
  earlier candidate.
- `dynamic_stgnn_feature_panel_phase2h_macro_v1.csv` and its permuted counterpart,
  `phase2h_macro_annual_features_v1.csv` — a macro-signal (INSEE/Banque de France) ablation;
  the macro features were not retained as primary inputs.
- `interim/atlas_iat/atlas_iat_ze2020_static_features_{v0,v1}.csv`, `static_feature_use_policy.csv`
  — a static ZE2020 context layer (306 zones, 25 columns, no nulls), closed as post-model
  overlay context. Does not replace any current training input.

## Source inventory

Raw downloads stay on the machine that fetched them, or on the cluster; the repository keeps
the ingestion script and the derived panel, not the raw file, as the reproducible unit (see
`../docs/DATA_AND_PROVENANCE.md` §5 for exactly what `.gitignore` excludes and why).

- Actively maintained sources: `metadata/HERALD_DATASETS_MAIN.md`
- Explored, not retained: `metadata/HERALD_DATASETS_EXPLORATORY.md`
- Update/API policy: `metadata/HERALD_DATA_UPDATE_POLICY.md`

## Do not cite as a canonical source

- Per-seed prediction files.
- `.npz` internals.
- Panels built for a single, one-off battery.
- Panels predating the current geo2025 boundary vintage, unless explicitly reading them as
  archive.
