## Naming Rule

- `Ridge annual baseline`: annual tabular benchmark.
- `Graph-Augmented RNN`: historical fixed-graph recurrent prototypes.
- `Dynamic STGNN`: future architecture with graph relations learned or updated over time.

Older files that contain `STGNN` in their name may be historical fixed-graph experiments. Check [PROJECT_JOURNEY.md](/home/jpdark/Downloads/project_recomm/dataset/reports/PROJECT_JOURNEY.md) and [report_consolidation_inventory_v1.csv](/home/jpdark/Downloads/project_recomm/dataset/metadata/report_consolidation_inventory_v1.csv) before interpreting them.

## Generated Artifacts

Top-level JSON and CSV files are not all canonical reports. They include:

- quality reports generated by data-build scripts;
- metrics generated by baseline or diagnostic scripts;
- diagnostic dumps used by historical analyses;
- reference bundles read by comparison scripts.

Do not move generated JSON/CSV artifacts into subfolders unless the corresponding scripts and references are updated first.

The current policy is:

- keep generated artifacts in place while scripts still use hardcoded `reports/...` paths;
- classify their role in [report_consolidation_inventory_v1.csv](/home/jpdark/Downloads/project_recomm/dataset/metadata/report_consolidation_inventory_v1.csv);
- move them only in a dedicated refactor phase.

## Cleanup Rule

No deletion should happen from `reports/` until:

- the file is marked as deletable in the inventory;
- the generating script is identified;
- no canonical document or script depends on the file;
- the deletion is explicitly approved.
